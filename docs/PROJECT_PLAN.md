# Project Plan

## Project definition

One Hologram-based Kanban application, developed and operated
through the complete software delivery lifecycle.

## Scope

- Kanban boards, columns, and tasks
- Task creation, editing, movement, and completion
- Persistent data storage
- Automated tests and CI
- OTP release and containerized execution
- Local multi-service environment
- AWS infrastructure managed as code
- Production deployment and automated delivery
- Distributed operation and scaling
- Centralized logs, metrics, dashboards, and alerts

## Delivery stages

- [ ] Stage 1: Requirements, architecture, and project management
- [ ] Stage 2: Verify the development toolchain and study Hologram integration
- [ ] Stage 3: Implement and test the application
- [ ] Stage 4: Build an OTP release and Docker image
- [ ] Stage 5: Establish a reproducible local multi-service environment
- [ ] Stage 6: Define and validate AWS infrastructure as code
- [ ] Stage 7: Deploy to AWS with cost controls
- [ ] Stage 8: Implement continuous deployment and secrets management
- [ ] Stage 9: Implement distributed deployment
- [ ] Stage 10: Evaluate scaling, health checks, and safe rollbacks
- [ ] Stage 11: Implement centralized logging and metrics
- [ ] Stage 12: Build dashboards, configure alerts, and validate operations
- [ ] Stage 13: Document the completed lifecycle and clean up unused resources

## Constraints

- Local-first development
- AWS credits currently reported: $119.70
- Credit expiry shown in the account: 7 April 2027
- Verify service eligibility, pricing, and credit terms before deployment
- Do not leave billable cloud resources running unnecessarily
- Record Hologram-specific differences from the book's Phoenix LiveView implementation

## Definition of done

The application has been tested, packaged, deployed, operated,
monitored, and documented. Cloud resources have been reviewed
and unnecessary resources have been removed.
